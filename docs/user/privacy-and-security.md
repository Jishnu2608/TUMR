# Privacy and security

- **Local only.** The runtime has no account, no cloud service and no telemetry. It contacts the internet only to download what you approved (from the official publishers), and to check for a newer version: when the app starts and when you run `tumr update`, it reads the project's release list on GitHub (`releases.json`, a few KB; no information about you or your projects is sent). It installs nothing without your click. Turn the check off with `manifest_url = "off"` under `[update]` in `%USERPROFILE%\.tumr\config.toml`. Android CLI is always run with `--no-metrics`.
- **Your system stays as it is.** Global `PATH`, `JAVA_HOME`, `ANDROID_HOME`, Android Studio and existing SDKs are never changed. Google's tools run in an isolated environment, so their settings and caches (emulator settings, Expo and Flutter state) stay inside the runtime's toolchains folder. One exception: adb writes its keys to `%USERPROFILE%\.android\adbkey` (and `.pub`) when it starts, as it does for Android Studio, which uses the same files. Administrator rights are asked for only two named actions (Windows Hypervisor Platform, long paths), each with its own Windows prompt.
- **Verified downloads.** HTTPS from an allowlist of official hosts, checksums checked before anything is unpacked or run, archives checked for unsafe paths and links. The main program of the JDK, Node.js, Git and the Android command-line tools must also carry its publisher's Windows (Authenticode) signature — Eclipse Foundation, OpenJS Foundation, the Git for Windows maintainer, Google — or the install is refused. The JDK zip and Node's checksum list are also checked against the publishers' GPG signatures (Eclipse Adoptium's key and the Node.js release keys, built into the app): a signature that does not match refuses the install; a signature made by a key the app does not know yet installs with a warning, on the checks above.
- **Project trust.** Building runs the project's own scripts (Gradle, npm, Flutter). Nothing builds until you trust the folder (`tumr trust`); agents cannot trust folders.
- **Local API.** The Runtime Core listens on a named pipe only your Windows user can open, and every client needs a token. The preview uses a loopback connection with single-use tokens.
- **Agents.** Limited permissions, approvals for new folders and device switches, an audit log, and sanitised output — see [Agents](agents.md).
- **Logs and records.** Logs are kept in `%USERPROFILE%\.tumr\logs`; old ones are removed by `tumr clean`. The database (`tumr.db`) is readable only by your Windows user (and SYSTEM / Administrators); audit-log entries and environment scans older than 90 days are deleted when the Runtime Core starts (`[storage] retention_days` in `config.toml`, 0 = keep them).

Report a vulnerability privately, as described in `SECURITY.md` in the repository.
